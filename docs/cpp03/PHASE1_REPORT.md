## Methodology

`tools/inventory.py` scans the private TXT line by line:

1. Running headers containing `DRAFT: 11 April 2004` define page boundaries.
   The page token is read from the start or the end of the header line.
2. Clause headings match `<number> <title> [<tag>]`. Annex headings match
   `Annex <letter> (informative|normative)` followed by a title line with a tag.
3. A subclause body runs from its heading to the next heading, excluding running
   headers and stopping before the document index.
4. Counts use these heuristics:
   - paragraph: a line starting with a number followed by two or more spaces;
   - grammar production: an indented lowercase hyphenated name ending with `:`;
   - table: a line whose caption starts with `Table <n>—`;
   - example: a line containing `[Example`;
   - note: a line containing `[Note`.
5. The fingerprint is SHA-256 of the normalized body, following
   `provenance/README.md`.
6. The page range of a clause is the range of its subclauses. A clause or annex
   that starts on its own first page is assigned `<prefix>-1`.

## Limitations

- Counts are structural estimates. Tables and examples that span several lines
  are counted once, at their caption or opening bracket.
- Grammar productions inside prose blocks may be undercounted or overcounted.
  Annex A is the authoritative grammar count.
- Candidate references include incidental numeric parentheticals that happen to
  match a clause number. They are inputs for review, not final dependencies.
- The document index (pages 0-1 through 0-35) is excluded from all clauses.

```text
python -m pip install -r tools/requirements.txt
python tools/inventory.py --source path/to/wg21-n1638.txt --private-out path/to/clause-map-private.yaml
python tools/coverage.py
python tools/validate.py
python tools/verify.py
```
