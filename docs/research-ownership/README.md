# C++03 research ownership

This metadata-only allocation implements #196 under [checklist #186](https://github.com/kniazkov/code-property-graph/issues/186).
It assigns all 5,250 overlapping source locators to exactly one research issue.
It does not count atomic requirements or establish source review, implementation
coverage, test execution or standards completeness.

## Inputs and outputs

`batches.json` pins the inventory byte hash and original-edition PDF identity.
The input is `../cpp03-paragraphs/inventory.json`, unchanged by this task.
Every batch lists exact IDs, source sections, kind counts and available footnote
call-site links. `owners.json` assigns one GitHub issue per batch; `index.md` is
the readable execution index. Existing topics #201–#226 own their first batches;
93 new continuation issues cover all remaining ranges, footnotes and the numbering anomaly.
Migration ownership in `../documentation-migration/` is independent of research
ownership: translating an old audit does not author or validate requirements.

## Boundaries

Batches follow source-page/section order within a topic, capped at 50 locators.
A section may span batches; adjacent sections may share a batch. No implied
range replaces the exact ID list. Sections can serve several topics; ownership
is administrative, not a claim that semantic dependencies stop at that boundary.
Footnotes retain global identity and available call-site links, including explicit
absence of a uniquely recovered call site. The numbering anomaly has a dedicated
classification task; do not invent paragraph text for it. Rejected extraction
candidates remain excluded by the source inventory.

Each task may review at most 60 new locators, including dependency/context reading,
and address at most three difficult edition/DR questions. The allocation reserves
up to ten additional locators; it does not automatically authorize a longer PR.
Author normally 15–25 requirement cards and at most 2,500 prose words. Split the
allocated batch before exceeding any limit, add the new issues to #186 and update
ownership atomically. Large tables can require a split even with few locators.

For each locator, record requirements, justified no-independent-requirement status,
or an explicit unresolved question. Overlapping grammar, tables and footnotes need
cross-links rather than duplicate obligations. Normative dependencies outside this
inventory are not falsely declared enumerated: every research owner must identify
its dependencies, link already-owned work, and register bounded follow-ups for
unowned external C/ISO/DR obligations before closing. Inventory membership alone
cannot settle normative versus informative status. No normative text is copied here.

Task branches and PRs target `documents`. CI remains disabled until final integration;
use local checks and restore the isolated CI commit according to #186. Source files,
parser behavior, historical evidence and the frozen migration census are unchanged.

## Reproduce and validate

From the repository root:

```sh
python3 scripts/inventory-research-ownership.py --check
python3 scripts/test-research-ownership.py
```

The generator without `--check` reproduces `batches.json`. Issue numbers are reviewed
metadata and must never be regenerated by creating duplicate GitHub tasks. The checker
rejects missing/extra owners, duplicate issue ownership, incorrect initial-topic
ownership and allocation drift. It also verifies locator uniqueness/counts, kinds,
source identity, physical pagination and call-site references. The readable index is
validated by the tests. No PDF interpretation or full native conformance run occurs.
