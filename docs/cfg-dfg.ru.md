# CFG и DFG

Первый PR добавляет в граф рёбра потока управления (CFG) и потока данных (DFG). Для них предусмотрены проходы в пакете `analysis` и отдельные цвета в SVG.

## Границы анализа

Каждая функция или метод анализируется отдельно. В выражении `int y = f(x);` DFG показывает передачу значения `x` в вызов и использование результата для инициализации `y`. Существующая ссылка вызова на объявление `f` сохраняет своё назначение. Межпроцедурные связи «аргумент → формальный параметр» и «return вызываемой функции → вызов» отложены.

## Детализация CFG

Вершинами потока управления служат исполняемые инструкции и выражения условий целиком. В конструкции `if (x > 0) y = a + b;` ребро `true` ведёт от условия к инструкции присваивания, а ребро `false` — к следующей инструкции после `if`, если она есть. Чтение отдельных операндов и сложение внутри инструкции отражаются на уровне зависимостей DFG.

## Записи, достигающие чтения

Для каждого чтения локальной переменной DFG содержит ребро от каждой записи в эту переменную, которая достигает чтения хотя бы по одному пути CFG без перезаписи. При слиянии ветвей множества таких записей объединяются.

В примере `int x = 0; if (flag) x = 1; else x = 2; int y = x;` к последнему чтению `x` ведут рёбра от присваиваний `x = 1` и `x = 2`. Обе ветви перезаписывают начальное значение. Если убрать ветвь `else`, по ложной ветви до чтения дойдёт инициализация `int x = 0`.

## Ветвления и циклы из исходников

В объём первого PR входит разбор `if` с необязательной ветвью `else`, `while` и базовых сравнений в условиях для Java и C++. Разбор использует существующие классы узлов. Примеры `if (x > 0)` и `while (i < n)` должны проходить весь путь от чтения файла до визуализации CFG и DFG через CLI.

## Вход и выход

Объявление служит входом. Каждая функция или метод с телом имеет одну служебную вершину `Exit` только в CFG. Каждый `return` ведёт к ней непосредственно. Попасть в неё также можно при обычном завершении тела. В пустой функции достаточно ребра от объявления к `Exit`. Недостижимые инструкции сохраняются в синтаксическом дереве.

## API, стадии и SVG

`ControlFlow.analyze(project)` возвращает новый снимок с CFG. `DataFlow.analyze(project)` добавляет DFG, при необходимости вычисляя CFG. Для DFG имена локальных переменных должны быть разрешены. `Project.flows()` содержит результаты по функциям с телом. В каждом `FunctionFlow` доступны `entry()`, `exit()`, `control()` и `data()`. Цели рёбер указывают на узлы данного снимка. Правка дерева через строители сбрасывает производные результаты.

CLI сохраняет только синтаксис на стадии `parsed`. На стадиях `resolved`, `green` и `folded` он строит оба потока после выбранного преобразования. Например, `--stage resolved --svg flow.svg` позволяет увидеть выражения до свёртки. Синие рёбра CFG подписаны видом перехода. Пурпурные рёбра `DFG value` показывают передачу значения операции, а `DFG def` соединяют достигающую запись с чтением. Пунктирное `ref` по-прежнему ведёт к объявлению. Явный путь из тела цикла ведёт к его условию, в том числе при пустом теле.

Анализ объединяет записи по возможным путям CFG и повторяет обработку до стабилизации, включая обратные рёбра циклов. Параметры дают начальные определения при входе. При присваивании правая часть может читать предыдущее значение переменной. Запись заменяет предыдущие определения только для того же объявления. Для аргументов вызова учитываются последовательность вычислений слева направо в Java и допустимые порядки C++17. Модель охватывает локальные переменные и параметры. Анализ памяти через указатели, эффектов вызываемых функций и выполнимости предикатов остаётся отдельной задачей.
